<p>一个十来人的团队，手上同时跑着五个项目，每个项目都要调 Claude API，于是很自然地想到"批量买更便宜"。真去谈批发才发现，供应商问的第一句是"你要多少条出口、绑多少个应用"，而你连自己该按项目分还是按人分都还没想清楚。批发的省钱效果取决于分组颗粒度：分得对，单价能降下来且运维量不变；分得错，地址买多了闲置、买少了互相挤，账单反而更贵。下面按团队规模分三层说清楚，每层该买到什么形态、怎么切分组、成本卡在哪儿。</p>

<h2>一、先用两条线把团队切开</h2>
<p>分层不按人数分，按两条业务线分：一是调用结构，看请求是持续低频还是短时高峰；二是归属关系，看出口是绑在项目上还是绑在人身上。这两条线交叉，基本能定位你在哪一层。</p>
<h3>调用结构决定要不要长期持有</h3>
<p>持续低频的调用，比如每天几千次、分布在十几个小时里，适合长期持有少量固定出口；短时高峰比如每天集中在两小时内跑完一批任务，按小时或按流量计费更划算，长期持有等于为闲置时间付费。</p>
<h3>归属关系决定分组怎么做</h3>
<p>出口绑项目，好处是成本能直接摊到项目预算里，坏处是项目结束出口就闲置；出口绑人，好处是人员复用灵活，坏处是人员变动时要重新分配并留下迁移记录。先定这条，再谈数量。</p>

<h2>二、第一层：单项目小团队，批发常常抬高持有成本</h2>
<p>只有一个主项目、调用量平稳的团队，最容易高估自己的需求。看到"批发价按阶梯走、买五十条打七折"就下单，结果五十条里长期在用的不到十条，剩下四十条每月照付，折扣全被闲置吃掉。</p>
<h3>先算真实并发，再算阶梯</h3>
<p>把过去三十天的请求日志按分钟聚合，取第 95 百分位的每分钟请求数，除以单条出口的安全并发，就是你需要的最小出口数。多数单项目团队算下来是两到四条，连第一档阶梯都够不上。</p>
<h3>用组合替代批发</h3>
<p>两条固定出口保日常，加一小段按流量计费的动态资源应对突增，比一次性买断五十条更贴近实际曲线。峰值过去动态资源不再计费，固定部分继续承载稳定流量。</p>

<h2>三、第二层：多项目并行，分组颗粒度直接决定账单</h2>
<p>项目一多，最容易出现的浪费不是买贵了，而是买重了。三个项目各自买了"独享"，实际调用峰值互相错开，同一时段只有一条在跑，等于付了三份钱买了一份保障。</p>

<h3>按调用曲线错峰合并</h3>
<p>把各项目的每小时请求量画在同一张图上，若两条曲线的高峰不重叠，可以共用一组出口，只需在配置里做好项目标识和配额上限，避免一个项目把并发吃满。</p>
<h3>按合规边界保持隔离</h3>
<p>有些项目必须独立出口，原因是数据处理要求或客户合同约定，这类隔离不能为了省钱合并。判断标准写在合同里，不写在运维的便利性里。</p>
<h3>给每个分组设配额上限</h3>
<p>在网关层对每个项目设每分钟请求上限和并发上限，超限返回明确错误码而不是静默排队。没有上限的分组，更容易出现一个项目把公共资源占满的情况。</p>

<h2>四、第三层：多成员协作，权限和计费要能拆开</h2>
<p>十几个人共用一批出口时，问题从"买多少"变成"谁在用、用了多少、出问题找谁"。这一层如果平台不提供子账号和用量明细，运维会退化成一张共享表格。</p>
<h3>子账号按角色分配</h3>
<p>至少分三种角色：管理员能改配置和换出口，运维能看日志和重启连接，业务方只能读取自己的用量。角色不分开，一次误操作就可能把整组出口换掉。</p>
<h3>用量明细要能按项目导出</h3>
<p>要求平台提供按分组、按天、按接口维度的用量导出，字段至少包含请求数、失败数、流量、峰值并发。缺这几个字段，月底对账只能靠估算。</p>

<h2>五、谈判桌上的四个成本杠杆</h2>
<p>批发价不是唯一变量。同样总价下，付款周期、替换政策、扩容速度和用量结转方式，对实际支出的影响可能超过折扣本身。谈的时候把这四项和单价放在一起比。</p>
<h3>替换政策比折扣更值钱</h3>
<p>问清楚每月免费替换几次、提交工单到生效多久、替换后是否保证同类型地址。一条每月便宜二十元但替换要等三天的出口，在故障当天的损失远超全年折扣。</p>
<h3>扩容与缩容的响应时间</h3>
<p>项目起量时能不能当天加出口，项目收缩时能不能当月减。缩容不灵活是批发最常见的隐性成本，因为闲置资源会跟着合同锁定期一起付完。</p>
<h3>用量结转与阶梯回跳</h3>
<p>按流量计费的方案要问清未用完的流量是否结转、下月总量回落后单价是否回跳。有些阶梯价按年度累计计算，有些按月重算，两种口径下的年度支出能差三成。</p>

<h2>常见问答</h2>
<h3>批发的起订量一般是多少？</h3>
<p>答：按条计费的产品常见十到五十条起订，按流量计费的池子往往没有硬性起订量，但会给阶梯折扣。具体门槛各平台不同，谈判前先问清阶梯的分界点和对应单价，再倒推自己落在哪一档。</p>
<h3>多个项目共用一组出口，会被判定为关联吗？</h3>
<p>答：存在这种可能，取决于项目之间是否需要隔离。如果几个项目面向不同主体、使用不同账号体系，共用出口会让行为特征混在一起。建议把需要隔离的项目单独成组，其余按调用曲线合并。</p>
<h3>闲置的出口能暂停计费吗？</h3>
<p>答：部分平台支持按月暂停并保留地址，暂停期间收取保留费或干脆不计费，各平台规则差异很大。签约前把暂停条件、最长暂停时长、恢复后地址是否变化这三条写进订单。</p>
<h3>怎么判断批发报价是否合理？</h3>
<p>答：把总价拆成单条月成本，再叠加替换频率、扩容响应和锁定期折算成年化支出，与零售方案做同口径比较。只比单价容易得出错误结论，因为批发的让步往往藏在条款里而不是标价上。</p>
